# Visual craft checklist

Use this after reading the existing brand and before polishing individual components. The checklist guides judgment; it does not prescribe one visual style for every product.

## 1. Start with a visual argument

- Name the screen's purpose and the one thing the user should notice first.
- Choose a composition that expresses the product's subject and task, rather than a familiar template chosen by habit.
- Use real product content, meaningful states and representative long data. Do not use filler copy or placeholder cards to make the page look complete.
- Keep the existing visual identity. If a different direction is justified, state why and update the project design record with approval.

## 2. Establish hierarchy and composition

- Group related information by meaning. Separate unrelated groups with alignment, position or space before adding containers.
- Use a small number of emphasis levels: primary, supporting and metadata. Let size, weight, contrast and position work together.
- Give each page one dominant region or action when the task calls for one. Data-heavy tools may prioritize a clear reading order rather than a CTA.
- Align edges and baselines deliberately. Use a grid for two-dimensional relationships and flexible rows/columns for one-dimensional flow.
- Avoid nested cards, repeated pill badges, unnecessary borders, decorative gradients and arbitrary icon tiles. Add a container only when it clarifies grouping or interaction.

## 3. Use spacing as information

Use the token scale consistently, but do not make every gap the same. Small gaps bind a label to its value; medium gaps separate related controls; larger gaps separate sections and page regions. Establish a recurring rhythm and use larger breaks only for meaningful changes in topic or hierarchy.

Choose density from the job: frequent monitoring and expert workflows may need compact rows; first-run, learning and reflective tasks need more breathing room. Preserve readable line length, click/touch separation and a clear focus target at every density.

If the existing scale cannot express a repeated need, propose a semantic token with a reason and add it through `client-branding`. Do not mint one-off component values.

## 4. Finish typography, surfaces and media

- Use the documented type roles and scale. Reserve the strongest size/weight for the main heading or value; keep metadata visibly subordinate but readable.
- Use color for identity or meaning, not to make every component different. Reserve feedback colors for their semantic state.
- Prefer surface contrast and alignment over heavy shadows. Use consistent radii and borders from the design system.
- Use purposeful imagery or product previews where they explain the subject. Respect source licenses, credits and image aspect ratios.
- Design empty, loading, error, partial, success and overflow states as part of the same system.

## 5. Inspect the finished screen

- Review at narrow, medium and wide widths; check long labels, long lists, empty and populated data, and zoom/text enlargement where possible.
- Inspect the full page, not only the first viewport. Look for accidental equal-weight sections, excess chrome, inconsistent spacing, clipping and awkward wraps.
- Use a real browser or provided screenshots when available. Treat automated visual detectors as a prompt for inspection, not as a substitute for judgment.
- Report which checks were actually run and what remains unverified.
