# Review gate

Freeze the integrated candidate and record a clean checkout, the comparison base, the candidate SHA and the passing local seam checks. Use the phase base for high-risk phase review. Use the original feature base and accumulated diff for final review. Apply project verification policy first and leave remote checks pending until observed.

1. Select reviewer roles and justify scope with `review-matrix.md`. Give them bounded, read-only access to the same frozen diff and ledger. Run independent reviews together when capacity permits, otherwise serially. Supply the diff and exact SHA from the coordinator if a read-only role has no shell.
2. Save unchanged structured verdicts in the feature's plan directory. Run `node <factory-workflow-path>/scripts/validate-review.mjs <review.json> <candidate-worktree>`. The input fields are `base`, `candidate`, `required` (role names), `requiredChecks` (exact local check commands from project policy), `checks` (records with `command`, `candidate`, `status`) and `verdicts` (records with `role`, `base`, `candidate`, `status`, `findings`, with a severity on each finding). The script verifies the checkout root, ancestry and clean tree. Record remote checks separately when pending.
3. For confirmed findings, assign corrections, integrate, run invalidated checks and freeze a new candidate. Reviews of a changed candidate must be fresh. A blocked or interrupted review can retry on the same candidate without consuming a correction round.
4. After three rejected correction rounds, stop attempting the same fix. Preserve evidence and only take another scoped step with a new hypothesis. Continue independent authorized tasks and report any remaining blocker. The coordinator never substitutes its own verdict for a required independent review.
