## Activation Contract

Use this skill when the user asks to create a new skill, add agent instructions, or document patterns for AI.

## Hard Rules

- A skill for every project lives in `skills/` of the `abraham-harness` repository. A skill for one project lives in `skills/{name}/` of that project, and `skill-sync` registers it. Never in `.claude/`, `.github/`, or `.opencode/` — those are generated by `skills/setup.sh`.
- Every new `SKILL.md` follows [`assets/SKILL.template.md`](assets/SKILL.template.md): sections in that order, using those exact headings. Omit Decision Gates, Execution Steps or Output Contract only when truly irrelevant.
- `name` matches the skill directory.
- `description` is one quoted line of at most 250 characters, with `Trigger:` first.
- The body stays within 4000 characters. Move long examples and background to the skill's `references/` or `assets/`.
- Links stay inside the skill directory, because installers copy one skill directory.
- Skills contain no details from a real project. Examples use the neutral `product`, `order` and `payment` domain and the `myapp` namespace.

## Decision Gates

| Situation | Action |
|---|---|
| A pattern is used repeatedly and the AI needs guidance | Create a skill |
| Project-specific conventions differ from generic best practices | Create a skill |
| Complex workflows need step-by-step instructions | Create a skill |
| The pattern is trivial or self-explanatory | Don't create a skill |
| It's a one-off task | Don't create a skill |

Naming conventions:

| Type | Pattern | Example |
|------|---------|---------|
| Generic | `{technology}` | `nestjs`, `react` |
| Project-specific | `{project}-{component}` | `app-product` |
| Workflow | `{action}-{target}` | `skill-creator`, `skill-sync` |

## Execution Steps

1. Create the skill with this structure:

```
skills/{skill-name}/
├── SKILL.md        # Required — main skill file
└── assets/         # Optional — templates, examples
```

2. Write `SKILL.md` from [`assets/SKILL.template.md`](assets/SKILL.template.md).
3. Add it to the **root `AGENTS.md`** Available Skills table:
   ```markdown
   | `{skill-name}` | {Description} |
   ```
4. Add auto-invoke row if applies (action → skill).
5. Add it to the relevant scope `AGENTS.md` (`apps/api/AGENTS.md` or `apps/client/AGENTS.md`).
6. Run `npm test` in `abraham-harness`, then release it so projects receive the skill with `npx skills update`.

## Output Contract

Checklist:

- [ ] Skill doesn't already exist (`skills/`)
- [ ] Name follows conventions
- [ ] Frontmatter complete
- [ ] Hard Rules clear
- [ ] Added to root `AGENTS.md`
- [ ] Added to scope `AGENTS.md` if relevant
